Heuristic 1:
Name: Avoid God-classes
Explanation:
God classes have too much responsibilties and make it hard for changes to be implemented later on without impacting other features
Heuristic 2:
Name: Encapsulation
All data should be hidden within its class.
Explanation:
Users do not need to know the code is working in the background if it is not necessary for their task. Reduces the chance that permanent code gets accidentally altered
Heuristic 3:
Name: Inheritance should be used only for true ‘is-a’ relationships
Explanation:
Proper inheritance should only occure if child B is parent A. This makes the code more intuitive by mirroring real world logic.
