Assignment 2 and Assignment 3 both implement the same ETL pipeline for processing product data from a CSV file, but they differ significantly in design structure. Assignment 2 follows a mostly procedural approach where all logic is contained inside one main class. File reading, validation, transformation, and output writing are handled sequentially within a single method. While functional, this design mixes multiple responsibilities together, making the code harder to maintain and extend.

Assignment 3 improves the design by introducing object-oriented principles and separating responsibilities into multiple classes. Instead of operating directly on raw arrays throughout the program, a Product class represents each product as an object with its own data and transformation behavior. Validation logic is moved into a separate utility class, and the overall ETL workflow is handled by a dedicated processor class. This separation makes the code more modular, readable, and easier to modify without affecting unrelated components.
Assignment 3 is more object-oriented because it models real-world entities using classes and objects rather than relying solely on procedural logic. Encapsulation is used by placing product data and transformation methods inside the Product class, which protects internal state and keeps related logic together. The design also demonstrates abstraction by separating validation and processing responsibilities.

To verify that Assignment 3 produced the same results as Assignment 2, the same test dataset was used for both implementations. After running both programs, the output files were compared side by side to confirm that the transformed data matched exactly. This testing confirmed that the object-oriented redesign improved the internal structure while preserving identical functionality and output.
